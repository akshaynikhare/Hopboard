# ---------------------------------------------------------------------------
#
# robots.txt is only read at the ROOT of an origin. The site used to deploy to
# https://akshaynikhare.github.io/RealtimeClipboard/ , which put this file in a
# subdirectory where no crawler would ever fetch it — the file that actually
# governed that origin lived in a different repository, so the sitemap below
# could not be declared from here at all and nothing had ever told a crawler it
# existed.
#
# Since the move to https://realtimeclipboard.com/ this file sits at an apex and
# is authoritative. Which also means a mistake in it is now capable of doing
# real damage rather than none: tools/site-check.mjs asserts the Sitemap line
# points at the canonical origin, and fails the deploy if it does not.
#
# ---------------------------------------------------------------------------
# Why there is no longer a Disallow for app.html
# ---------------------------------------------------------------------------
#
# The previous version blocked app.html, and the reasoning was backwards. A page
# blocked by robots.txt is never fetched, so its noindex is never read, and
# Google stays free to list the bare URL on the strength of the links pointing
# at it. index.html links to app.html three times. Blocking is how you get the
# app indexed as a naked URL, not how you keep it out.
#
# app.html carries `noindex, nofollow, noarchive, nosnippet, noimageindex`.
# Letting crawlers fetch it is exactly what makes that tag work.
#
# There is also nothing there to protect. The session key lives in the URL
# fragment, which is never sent to a server and is not a distinct URL to a
# crawler. Googlebot rendering app.html gets an empty app with no key in it.

User-agent: *
Allow: /

Sitemap: https://realtimeclipboard.com/sitemap.xml
